## 🚀 3. Experience and Insights from Mission 10

Mission 10 was a challenging but valuable activity because it required me to work with several technologies within a single environment. Unlike the previous exercises that focused on specific tasks, this mission required me to understand how the different components connect and function as one system.

### 🐳 Docker and Docker Compose

One of the things I learned from this activity was how Docker and Docker Compose make application deployment easier to manage. Docker provides a way to run applications inside containers together with the necessary dependencies, helping maintain a consistent and organized environment.

I also gained a better understanding of Docker Compose and how it allows multiple services to be configured and operated through a single YAML file. Setting up the application and database containers helped me see how services communicate with each other and work together to make an application run.

### 💾 Persistent Volumes and Data Storage

I also learned why persistent storage is important when working with containers. At first, I understood that data stored inside a container could be lost when the container is removed or recreated, which makes it important to have a separate way of keeping important information.

Using persistent volumes helped me understand how database records can remain available even when containers are restarted or replaced. This made me realize how important proper storage management is, especially when handling information that an application depends on.

### 🔐 Server Security and UFW Configuration

Another important part of Mission 10 was configuring server security through UFW (Uncomplicated Firewall). This activity helped me understand how a firewall controls network connections and limits which services can be accessed from outside the server.

By applying a default-deny policy for incoming connections and allowing only the required ports, I learned how unnecessary network access can be restricted. It also showed me why protecting a server should be considered from the beginning of an infrastructure project.

From this experience, I understood that security is not something to overlook because it plays a major role in protecting the entire system.

### ⚙️ Bash Scripting and Cron Automation

Working with Bash scripting and Cron also gave me useful knowledge about automating system tasks. I learned that some administrative activities can be performed automatically instead of having to execute them manually every time.

Creating a script for tasks such as database backups and scheduling it through Cron helped me understand how automation works in a server environment. It showed me how scheduled processes can make system management easier and more organized.

I realized that automation is useful because it reduces repetitive work, saves time, and helps ensure that important maintenance activities are performed regularly.

### 📚 Technical Documentation and Project Organization

Aside from the technical configurations, I also learned that proper documentation is an important part of completing an infrastructure project. Preparing the README file, architecture diagram, operational manual, and other project documents helped me understand the value of organizing and presenting technical information.

Documentation serves as a guide for anyone who needs to understand, deploy, or maintain the system. It also provides useful instructions when troubleshooting problems or making changes in the future.

## 🛠️ 4. Challenges Encountered and Lessons Learned

During Mission 10, I experienced how challenging it can be to manage several technologies in one environment. Since the application, database, network, storage, and firewall configurations are connected, an error in one part can sometimes affect the operation of the entire system.

Because of this, I learned to be more careful when checking configurations and identifying errors. Rather than changing settings without knowing the cause, I realized the importance of examining the problem first, checking whether services are running, reviewing configuration files, and looking at error logs before applying a solution.

I also discovered that seeing a container in a running state does not necessarily mean that the application is working correctly. It is still necessary to test the connection between services and make sure that the application can access the resources it needs.

Another lesson I gained was the importance of preparing everything properly before deployment. Configurations involving security, storage, and backups should not be treated as minor details because they help keep the system stable and protect important data.

Even though some tasks took more time and required repeated checking, these experiences helped me become more patient and systematic when handling technical problems. I learned that errors are normal when exploring unfamiliar technologies, and each problem provides an opportunity to understand the system better.

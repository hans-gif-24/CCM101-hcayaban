# 🤔 Reflection — The Cloud-Native Engineer

This mission was a meaningful learning experience because I had the opportunity to work with **Docker containers** and apply what I learned through actual practice. Before doing this activity, I was a little confused about the differences between Virtual Machines (VMs) and containers. However, after studying their features and comparing them, I learned that containers are generally lightweight, start faster, and use fewer resources than virtual machines. This helped me understand why containers are useful in cloud-native development.

One of the activities I enjoyed most was practicing Docker commands in the terminal. I started by using `docker --version` and `docker info` to check the Docker installation and environment. After that, I downloaded the Nginx image and created my first container using the command `docker run -d -p 8080:80 --name nginx-server nginx`. When I used `curl http://localhost:8080` and saw the Nginx welcome page, I felt happy because I successfully deployed a working web server using only a few commands. It also helped me understand how Docker images and containers work together.

During the activity, I encountered a challenge when I tried to access the Nginx webpage through my browser. At first, I thought that typing `localhost:8080` would be enough, but the page did not appear as expected. I later discovered that KillerCoda uses a remote cloud environment, so I needed to use its **Traffic** feature to access the web server. After figuring this out, I was able to view the page successfully. This experience taught me more about port mapping, network access, and the differences between local and remote environments.

Another important lesson I learned was how to manage the **Docker container lifecycle**. I practiced commands such as `docker ps`, `docker stop nginx-server`, `docker ps -a`, and `docker rm nginx-server`. These commands helped me understand how to check running containers, stop them properly, verify their status, and remove them when they are no longer needed. By following these steps, I became more familiar with managing containers and keeping the Docker environment organized.

Aside from learning Docker commands, I also realized the importance of troubleshooting and being patient when working with technology. Not everything worked immediately, but by checking my commands and exploring the available features, I was able to solve the problems I encountered. This reminded me that technical skills improve through practice, experimentation, and learning from mistakes.

Overall, this mission helped improve my knowledge and confidence in using Docker and working with cloud-based environments. I also gained experience in writing Markdown documentation and organizing my work in my GitHub portfolio. Through this activity, I learned that cloud computing is not only about understanding concepts but also about applying them in real situations. As a future IT professional, I believe these skills will be useful in learning more about application deployment, container management, and cloud-native technologies.
